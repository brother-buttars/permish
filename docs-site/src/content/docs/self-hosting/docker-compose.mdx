Permish runs as a single backend service plus the SvelteKit frontend. An optional `production` profile adds Caddy for automatic HTTPS.

## Prerequisites

- Docker Engine 24+ and Docker Compose v2
- A Linux VPS (Ubuntu 22.04+ recommended) with at least 1 GB RAM
- A domain name with DNS A record pointing to your server (for HTTPS)
- Ports 80 and 443 open in your firewall (for HTTPS)

## Standard Deployment

The default deployment. A single Bun + Hono server handles auth, CRUD, PDF generation, email, and SMS, backed by SQLite (`bun:sqlite`).

```bash
git clone https://github.com/brother-buttars/permish.git
cd permish
cp .env.example .env
# Edit .env with your values (JWT_SECRET, email settings, etc.)

docker compose up -d
```

This starts two services:

| Service    | Port | Description                          |
|------------|------|--------------------------------------|
| `server`   | 3001 | Bun + Hono API server (SQLite)       |
| `frontend` | 3000 | SvelteKit app (server-rendered)      |

Access the app at `http://your-server-ip:3000`.

## Production HTTPS

Add automatic HTTPS with Caddy via the `production` profile. See [HTTPS & SSL](/permish/self-hosting/https-ssl/) for full details.

```bash
DOMAIN=permish.app docker compose --profile production up -d
```

This adds the `caddy` service (ports 80/443), which terminates TLS and proxies `/api/*` to `server` and everything else to `frontend`.

## Docker Volumes

All persistent data lives in Docker volumes, which survive container rebuilds:

| Volume            | Contents                          | Container path |
|-------------------|-----------------------------------|----------------|
| `db-data`         | SQLite database (`permish.sqlite`)| `/app/data`    |
| `pdf-storage`     | Generated PDF files               | `/app/pdfs`    |
| `uploads-storage` | Uploaded event attachments        | `/app/uploads` |
| `caddy_data`      | TLS certificates (production)     | —              |
| `caddy_config`    | Caddy configuration state (production) | —         |
