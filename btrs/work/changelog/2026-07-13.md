## Tauri desktop sidecar removed (build un-broken)

**Agent**: btrs-desktop-engineer
**Decision**: The desktop/mobile app is self-contained — local data uses native SQLite via
`@tauri-apps/plugin-sql` (rusqlite) and PDF generation runs client-side (`frontend/src/lib/services/pdf.ts`,
pdf-lib). Nothing in the frontend calls a local server. So the dead PocketBase + Node sidecar
wiring was **removed**, not migrated to a compiled Bun-server sidecar (which would serve nothing).
The old wiring also **panicked at startup** (`.expect("failed to find pocketbase sidecar")`) on the
missing binary, so the desktop build was fully broken.

### Changes
- `frontend/src-tauri/src/main.rs` — stripped `SidecarState`, `wait_for_pocketbase` (reqwest), both sidecar spawns, and the exit-time kill logic. Now just registers the shell/process/dialog/sql plugins.
- `frontend/src-tauri/Cargo.toml` — removed the `reqwest` dependency (only `wait_for_pocketbase` used it).
- `frontend/src-tauri/tauri.conf.json` — removed `externalBin`; dropped the sidecar `shell.scope` (kept `shell.open`); stripped the dead `http://127.0.0.1:8090` / `:3002` origins from the CSP `connect-src`.
- `frontend/src-tauri/capabilities/default.json` — removed sidecar-only `shell:allow-execute/spawn/stdin-write/kill` (kept `shell:allow-open`).
- Deleted `frontend/src-tauri/sidecars/` — the `README.md` plus ~95 MB of uncommitted, now-unreferenced `pocketbase` + `node-sidecar` binaries.

### Docs updated to "self-contained, no sidecar"
